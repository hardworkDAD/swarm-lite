# SWML（Swarm Lite）：主从隔离研发调度协议（主会话控制面 + 执行面 Hydrogen）

本技能仅定义**上下文隔离与跨模型执行调度方式**，与会话中同时激活的任何设计、规范或工作流技能正交叠加，互不覆盖。

**用户显式模型授权声明**：用户主动输入 `/swml`（或要求启用主从隔离模式）即代表**用户显式指定所有执行面 Worker 默认固定绑定 `model: "gemini-4-hydrogen-high"`**（除非用户显式要求切换为其他执行模型；该授权覆盖 `swarm` 默认继承主会话模型的规则，严禁省略 `model` 参数导致回退至主会话模型，且严禁改用不支持该执行模型路由的 `invoke_subagent`）。

## 1. 控制面与执行面边界（按信噪比切分）
- **主会话保留纯控制面（当前所选主模型，如 Neon / Carbon / Opus 等）**：仅负责需求交互、方案设计、配合其他活跃技能维护设计文档、首轮 1 次轻量环境预检、局部小范围代码抽检（`read_file`），以及最终只读的 `git status` 与 `git diff` 审计；**严禁在主会话内联执行任何高噪音构建、测试验证、联调脚本或批量文件操作**。
- **Hydrogen Worker 全权接管执行面（`swarm` 默认锁定 `gemini-4-hydrogen-high`）**：凡涉及 I/O 噪音、长耗时或迭代试错的任务——跨目录检索、大文件/日志读取、业务与测试源码修改、**全部构建与单测、外部环境/容器验证、显式委托的 HTML 页面渲染（`am render`）、端口联调、本机部署及 Git 写操作（含需 `BypassSandbox: true` 跨沙箱提权的命令）**——一律交由 `swarm{action: "add", name: "<phase>-<module>", model: "gemini-4-hydrogen-high", brief: "..."}` 执行，将海量编译/测试日志彻底封锁在执行面上下文内。
  - **轻量化纪律**：仅按需创建业务执行 Worker，**严禁**创建 `narrator`、`monitor` 或专职审查员等伴生开销角色。
  - **微改直通与同模自适应**：无在途 Worker 时的纯文档/配置改动或 **≤5 行零试错确定性微调**，允许主会话直接 `edit_file`，避免冷启动调度开销倒挂；若用户已将主会话模型切换为 `Hydrogen` 系列（主从同模），仅在多文件改动或高编译/测试日志噪音任务下启用 `swarm` 隔离上下文，简单单点任务可直接内联完成。
- **阶段自适应礼让**：若当前处于只读模式（如 `Plan` 模式），或正处于其他技能驱动的交互访谈/方案起草阶段，仅允许派发 `explore-<module>` 只读检索 Worker 提供事实支撑，并在结论上板后立即 `kill` 清零探索噪音；待进入实质编码阶段后再按模块新建干净的 `code-<module>` Worker 执行编码闭环。

## 2. 看板原生无损共享与零空转启动协议（收发无损 + 滤除刷屏噪音）
为消除启动空转轮次与无效报错，主会话不创建 `.agents/.brief.tmp.md` 等冗余协议文件，严格按以下规则组装看板指令：

1. **首轮轻量环境预检与沙箱边界防呆（Pre-flight Check）**：
   - 派发首批 Worker 或发布全局主规格帖前，主会话先用 1 次零噪音只读检查摸清工作区构建/测试布局、沙箱内外边界（识别只读挂载、外部服务/端口，以及**可写临时 `tmpfs` 遮罩目录**如 `~/.gemini/antigravity-cli`、`~/.local/bin`、`~/answer-me-with-html` 等）与工具/权限约束（有无 `rg`、是否拦截 `rm -f`），将环境事实一次性写入主规格帖：
     - **先沙箱试跑、遇阻/遮罩再同摘要提权**：所有需跨沙箱的命令遵循先在 `BypassSandbox: false` 试跑一次；若报只读/权限错，或涉及**可写临时 `tmpfs` 遮罩**（在默认沙箱下看似返回 0 实则仅写入临时内存盘），必须保持完全相同的 `toolSummary` 改传 `BypassSandbox: true` 以独立单条命令重试（无 `&&`/`;`/`$(...)`，便于前缀自动放行），并在宿主实盘核验 SHA-256 / `mtime` 确认落盘生效。
     - **明确禁用拦截命令**：如禁调 `rm -f`（改用 `node -e "fs.rmSync(...)"` 或安全移除方式）。
2. **会话内背景、规格与前序结论 100% 无损上板**：
   - 凡是在主会话中形成的任务背景、设计方案、接口签名、公式/状态转移逻辑、边界条件、修改文件白名单与验收标准，**取消字数上限、严禁人为缩略删减**，完整发到公共看板。
   - 若下游 `code-*` 承接前序 `explore-*` 的复杂结构事实（如数据库 DDL、Protobuf tag、报错栈），**可直接指令下游调用 `read_board(seqs=[<主规格seq>, <explore结论seq>])`** 零损耗继承原文，既省复述开销又避免漏抄导致中途反问停顿。
3. **在盘文件强制拼工作区绝对路径 + 保留精确行号**：
   - 仓库内已落盘的文档与源码不往看板复制粘贴原文，但**主会话必须提供完整绝对路径及已知行号区间**（如 `/abs/workspace/src/foo.js:698-715`，严禁只丢裸文件名害 Worker 全盘 `find`）。
4. **单次发帖 + 看板 `#seq` 安全共享**：
   - **单 Worker**：将完整背景、任务指令与下方【Worker 执行铁律】一次性写入 `swarm{action: "add"}` 的 `brief`（Worker 首步直接读目标业务代码，零额外读盘轮次）。
   - **多 Worker 并发**：完整共享背景、全局规格与【Worker 执行铁律】**只在看板发 1 次**（放入独立 `post_message` 规格帖或首个主 Worker 的 `brief`）；其余并行 Worker 的 `brief` 写明 `先调用 read_board(seqs=[<主规格seq>]) 获取完整规格与执行铁律，你专属负责……`（禁止无故调用无参 `read_board`）。**序号安全约束**：仅在当前零活跃 Worker 时才可同轮预测 `head + 1`；若仍有在途 Worker 可能并发发帖，应先发主规格帖取得返回 `seq` 后再派发并行分片。
5. **必附内联【Worker 执行铁律】页脚**（直接附在主规格末尾，省去外部读盘轮次）：
   ```text
   【Worker 执行铁律】
   1. 工具与路径：read_file/edit_file/write_file 的 Path 必须传绝对路径（禁传相对路径）；终端文本检索用 grep -rnE 并限定在源码目录（排除 build*/dist*/node_modules/.cache/.git，勿假定有 rg）；禁调 rm -f；严禁无故调用无参 read_board。
   2. 按窗精读：若指令给出了行号区间，首轮用 StartLine/EndLine 按目标前后 ±40 行窗口分段读取，严禁一上来整文件盲读上千行。
   3. 反作弊、测试隔离与熔断（编码模式）：仅改授权白名单文件；严禁删改/跳过/弱化现有单测或断言容差、严禁滥用类型强转逃生舱、严禁空 catch 吞异常；任何单测严禁直接覆写仓库内真实配置/源码或宿主机真实数据目录，必须使用临时目录 + 环境变量重定向隔离并在 finally 清理。编译/语法报错最多修 3 次，算法/断言失败最多修 2 次，超限立即停手发 `@coordinator [CIRCUIT_BREAK]`。
   4. 无损回包、渲染边界与去噪：向主会话交卷或遇阻时用 post_message 以 `@coordinator` 开头汇报；默认严禁私自渲染 HTML 页面或建子代理（仅在主会话显式委托执行 `am render` 时允许渲染并仅返回 `.html` 路径与校验输出）；若按指令点对点交接给下游同伴（如 `@test-runner`），只 `@` 下游同伴名，正文中严禁出现 `@coordinator` 字面量以免误唤醒主会话。回包不设字数上限，必须完整汇报所有事实结论、精确 filepath:line、变量/接口签名、完整公式推导、分支与边界条件，仅过滤大段无关源码倾倒与全量通过的刷屏日志（失败时贴关键报错栈与残差）。
   ```

## 3. 按 `<阶段>-<模块>` 换血、分片与并发安全
- **统一命名规范（`<phase>-<module>`）**：使用 `explore-<module>`、`code-<module>`、`test-runner-w1` 等阶段前缀命名，既隔离职责边界，又天然规避 `swarm` 已 `kill` 名称在同一会话内不可重用的限制。
- **跨阶段强制换血（`explore-*` ➔ `kill` ➔ `code-*` 及 `test-runner` 定期换血）**：
  - 只读探索 Worker（`explore-*`）将提纯后的无损结论发上公共看板后，**立即调用 `swarm{action: "kill", name: "explore-..."}` 销毁**，将探索期的检索噪音彻底清零。
  - 方案拍板进入编码期时，**重新 `add` 全新的 `code-*` Worker**，仅读取看板定稿规格（及按需直读的 `explore` 结论 `#seq`）和白名单内目标文件，保证执行面上下文极简聚焦。
  - **测试执行器定期换血（`test-runner-w1` ➔ `kill` ➔ `test-runner-w2`）**：长链路多轮迭代中，`test-runner` 每完成 **2～3 轮**构建测试收口后立即 `kill` 销毁并按需新建下一代实例，清空累积输出缓存；多包工程汇总测试结果时按目标包隔离结果目录，避免混入其他包历史残留报告。
- **按模块边界事前分片与串行收口构建（事前控粒度，事中不换人）**：
  - **单模块改动（1～2 个核心实现文件及配套单测）**：1 个 `code-<module>` 完整跑完改码与单测。
  - **跨子系统或中大型任务**：在派发前按子系统并行拆 `explore-a` / `explore-b`；编码期按互斥文件拆 `code-a` / `code-b` 并行改码，要求各实例**“仅改授权文件、仅做语法检查/所属单测、暂不运行全量构建与宿主机部署”**；若有共享注册/清单文件（如构建脚本、路由/模块导出索引），必须在派单前将其**唯一划归其中 1 个实例**统一预注册，严禁双写踩踏；待全部 `@coordinator` 交卷后，仅指定其中 **1 个** 实例（或新建干净的 `test-runner-w*`）串行执行全套构建、全量单测、宿主机/容器部署与联调，防止构建锁冲突。
  - **多清单逐单提交的水位控制（WIP ≤ 2）**：当任务包含多张需独立 `git commit` 的清单且共用同一工作树（`workspace: "inherit"`）时，严格控制未提交在途清单不超过 **2 张**——优先保障 1 张主路径清单走完“改码 ➔ 全量验证 ➔ 主会话只读 `git diff` 终审 ➔ Worker 精准 `git add/rm/commit` 落袋 ➔ `kill`”，后台至多超前预写 **1 个**零共享文件的独立模块，防止未提交改动交错堆积。
  - **严禁编码中途换人交接半成品**：单实例上下文靠“跨阶段换血 + 事前模块分片 + `±40` 行按窗精读 + 3/2 次报错硬熔断”控制，严禁在同阶段改码中途强行 `kill` 换新实例重读半成品改动。
- **终审与提交收口保活（落袋后再 `kill`）**：
  - Worker 完成全套构建验证（含宿主机实盘核验）交卷后保持 `waiting`（0 Token 待机）；主会话仅执行轻量只读 `git status` / `git diff` 终审——若发现瑕疵直接 `post_message` 唤醒原实例秒改，若终审通过则唤醒该实例执行精准 `git add/rm/commit`（或无需提交时直接放行），**落袋后再统一 `kill` 清场**。
- **同轮静默直挂与零尸体噪音（禁空停、禁轮询、禁例行查 `status`）**：无论是否首轮创建 `swarm`，派发 `add` 或 `post_message` 后均在**同一回合直接调用 `swarm_wait{since: <派单前已读最大seq>}`** 0 Token 静默挂起（仅在里程碑完成或需用户决策向用户输出时附上 `open_board` 即可）。**严禁每次 `add` 后例行调用 `swarm{action: "status"}`**（避免长会话全量返回历史 `killed` 列表污染主会话上下文；`add` 返回 `added` 即已自动点火，仅在长时间无响应疑似异常时按需排查）。

## 4. 对齐终审与熔断接管
- **全维度只读 `git diff` 终审**：Worker 完成全套构建、测试与宿主机实盘验证后，主会话执行只读 `git status` 与 `git diff` 审计：对照看板完整规格、活跃技能规范与仓库规则文件，核验逻辑完备性、边界/并发安全、性能影响，严查跳过测试、弱化断言、静默吞异常或单测污染工作区等作弊行为；过审后指令 Worker 完成 Git 提交（如需要）并执行 `kill` 清场。
- **熔断直接接管**：若 Worker 返回 `[CIRCUIT_BREAK]` 卡在核心算法或复杂状态推导上，主会话直接推演根因并动用自身编辑工具（`edit_file`）精准修复难点，随后唤醒该处于 `waiting` 的 Worker 完成回归测试。
